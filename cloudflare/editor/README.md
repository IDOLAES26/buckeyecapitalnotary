# Buckeye Studio

Visual editor for Buckeye Capital Notary. The existing public website remains on GitHub Pages. This new private editor runs in a separate Cloudflare Worker.

## Preview now

Download `Buckeye-Studio-Preview.html` and open it in a desktop browser. Double-click text on the canvas to type directly. Click outside the text to finish; use Enter for line breaks. Select an element to reveal floating controls for text size, color, alignment and movement. Shift-click elements to select several, or enable **Multi-select** and click them. Enable **Drag elements** to drag the selected items together, or use the floating Move handle. Nested selections move once with their selected parent. Click **Select only** or press Escape to return to one element. Click **Section** on the floating toolbar (or select a section in the left panel), then drag its bottom-right ↘ handle to resize its width and height. Padding and width/height fields remain available for exact sizes. Fixed section heights may let overflowing content extend past their edges; review all content after shrinking a section. Drop a PNG, JPEG, WebP or GIF file under 2 MB onto an existing image to replace it. The right panel remains available for detailed controls. Then use Preview. Choose Desktop, Tablet, Mobile, or Small mobile before making screen-specific changes. The default scope is the selected screen; “All screens” changes the shared baseline. Existing screen-specific overrides take priority.

Text, links and buttons, images, illustration shapes, backgrounds, borders, divider lines, fonts, spacing, widths, alignment, grid columns and visual positions have controls. Select parent selects a surrounding container. The drag handle changes visual position; grid and spacing controls rearrange layout flow. Text accepts deliberate line breaks. Very narrow screens can still wrap a line that is too wide; reduce the font size or shorten it in that screen's view.

Local Save draft downloads a JSON project; Import project restores it. Keep that project to continue editing. Export downloads website HTML. Local mode does not publish. The editing canvas disables scripts. Interactive preview runs the site scripts with sample search/fee responses while blocking real submissions and API calls. Real routing and email integrations must still be checked separately on a staging or deployed site. Link URLs and uploaded images are shared across screen sizes; text and visual styles have separate screen overrides.

## Deploy the private editor

Create a **new** Cloudflare Worker named `buckeye-site-editor`. Leave the existing `buckeye-notary-fees` Worker alone. Paste the entire generated `worker.mjs` into its code editor and deploy. The Worker returns a setup error until authentication is configured; it never falls back to a public editor.

1. Configure a Cloudflare Access application protecting the entire new Worker hostname and all paths. Use an allow policy restricted to your own email. Enable Access protection for the workers.dev hostname through the Worker's domain settings if using that hostname. Use a custom editor hostname protected by Access if your dashboard does not expose that option. The server verifies Access tokens even if a hostname is accidentally left unprotected.
2. Add Worker text variables `ACCESS_TEAM_DOMAIN` (your team's `something.cloudflareaccess.com` domain), `ACCESS_AUD` (this Access application's audience tag), and `EDITOR_EMAIL` (the exact email you will sign in with). Use your own email consistently in Access and this variable.
3. Create a Workers KV namespace called `buckeye-editor-drafts` and bind it to this Worker as `EDITOR_DRAFTS`. Saved drafts are private snapshots. Save project downloads as backups too; cloud drafts are not automatically deleted.
4. To enable publishing, create a GitHub fine-grained token restricted to `IDOLAES26/buckeyecapitalnotary` with repository Contents read/write permission. Save it as Worker **secret** `GITHUB_TOKEN`. Enter it directly in Cloudflare, never in this repository, the editor, or chat. Keep `ENABLE_PUBLISH` unset while checking draft editing. Then set `ENABLE_PUBLISH` to `true` when ready to allow reviewed publishing.
5. Sign in to the new editor URL, verify all four screen views, save a draft, reopen it, and use Review & publish only when the result is ready. Publishing checks the original source version and preserves the site's scripts and appointment field names/action. It commits only `index.html` on `main`; GitHub Pages then deploys that commit. A stale draft is blocked rather than overwriting a newer website. Export stale work for a manual merge.

No billing setup is implemented by these files. Usage and availability are governed by your Cloudflare/GitHub account plans. No live browser or deployed Cloudflare test has been completed in this workspace; deployment and a signed-in end-to-end review are still required.

## Build and verify

Run `npm install`, `npm run build`, and `npm test` in this folder. Node 22 or later is recommended. `source.html` is the starting public-site snapshot; the hosted editor fetches current `index.html` from GitHub when opened. `build.mjs` contains the matching initial source SHA: update it when replacing the bundled snapshot. Generated outputs are `Buckeye-Studio-Preview.html` and `worker.mjs`.

Tests cover independent screen copy, repeated export/reopen, preservation of form connections and scripts, rejected unsafe CSS and link protocols, signed Access tokens, expiry and email checks, cross-site request rejection, disabled publishing and missing storage. Direct canvas typing, floating size controls and screen-scoped pointer dragging are covered by DOM interaction tests. They do not substitute for browser layout review or a real Access/KV/GitHub publishing test.

## Expanded editing tools

- **Layers:** All elements appear in the searchable layer list. Select a row to inspect it, rename it with Layer name, use its lock control, or hide/show it in the current screen scope. Locking a parent also locks its children. Layer names and locks are editor metadata and are not added to the public page.
- **Alignment:** Shift-click or Multi-select several elements, then use Left, Center, Right, Top, Middle, Bottom, or equal spacing. Snap to alignment guides shows pink guides while dragging near other elements. Selected children move only once with a selected parent.
- **Duplicate / delete:** Duplicate copies a visual element and its screen overrides. Delete applies to selected top-level elements across screen sizes. Undo restores deleted items. Elements containing the appointment form, navigation controls, or IDs required by the site's scripts are protected from destructive structural operations.
- **Sections:** Add section creates a heading and paragraph in a new page section. Select a section to duplicate/delete it or move it up/down. Structure is shared across screen sizes; position, size, crop and text styling remain screen-scoped.
- **Local recovery:** A recovery copy is written after edits in this browser. Reopening the same editor file offers restoration. Restore recovery is available manually. Browser restrictions, private browsing, clearing browser data, changing the editor file location, or exceeding storage quota can prevent recovery. The recovery indicator reports failures; downloaded project backups remain essential.
- **Images:** Set a frame size, choose Crop / zoom and Crop X/Y, then Apply crop / zoom. These visual crops preserve the original image URL/file. Keep image proportions controls corner resizing. The HTML hero illustration remains a collection of shapes rather than a photograph.
- **Responsive checks:** Check layouts examines desktop, tablet, mobile and small mobile using the currently selected appointment form step. It flags out-of-screen content, overflow, clipped text, content beyond section bounds and likely overlaps. Click a finding to inspect it. These are heuristics; intentional overlaps can be flagged and some issues can be missed. Review each form step and the interactive preview too.
- **Interactive preview:** Website scripts run in an isolated sandbox with no same-origin access to the editor. Menus, FAQs, dialogs, validation and appointment steps can be exercised. Location search uses labeled SAMPLE locations; fee calculations use a labeled $30 sample travel charge plus $5 per sample act. External API requests and form submissions are blocked. This checks the interface, not the live routing/email integrations. Use test details only.

`extras.js` implements editor-only features and is embedded by the build. `editor-tools.test.mjs` exercises layer handlers, section changes, duplication, locking, geometry calculations, crops, recovery and the preview guard. Browser rendering, real pointer behavior, and Cloudflare integration still require an end-to-end browser review.
